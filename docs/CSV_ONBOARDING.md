# CSV household onboarding

DSWD can use **Import a CSV** under **More registry options**. The old **Analyze a CSV** remains a separate read-only analyzer for its historical sample format.

Choose an active batch and a UTF-8 file with beneficiary_id, household_name, barangay_id and barangay_name headers. Optional fields are dafac_id and contact_number. Download the fictional import sample in the dialog. Files are limited to 128 KiB and 200 rows. Import references accept letters, numbers, dots, underscores and hyphens; text lengths and control characters are validated. Unknown/mismatched barangays, existing household IDs (including history), repeated IDs, malformed quoting and column errors cannot be silently skipped or overwritten.

**Preview selected CSV** shows each row's errors and up to five strongest possible matches against the existing registry, retained duplicates and other rows in the file. DAFAC equality and deterministic name/locality similarity are review suggestions, not identity proof. A valid preview creates a private actor-bound plan; it does not change the household registry or eligibility. All errors must be corrected before importing. No partial import is offered.

**Import pending households** explicitly adds every validated row as FLAGGED_FOR_REVIEW/PENDING, including rows without matches. It does not approve aid, link duplicates, delete history or record payouts. The saved confirmation offers each imported household's existing registry/review journey. DSWD uses the normal reasoned human review and retained-duplicate controls afterward.

## API and durability

POST /api/beneficiaries/csv/preview accepts batch_id and csv_content. POST /api/beneficiaries/csv/{import_id}/import accepts the saved plan reference only, so callers cannot substitute rows after preview. Both require an authenticated DSWD session and existing CSRF/origin protection. Plans belong to the creating account and expire after 30 minutes unless already imported. A changed registry or inactive batch requires a fresh preview. On SQLite, a writer lock covers rereading the plan/registry and atomically writing households, the actor-attributed local CSV_IMPORTED audit event and the replayable result. Repeated or concurrent requests for the same saved plan return that result without inserting again, including after a lost response. Another account cannot claim the plan. No new chain evidence is claimed for imports or the local audit.

The new csv_imports table is additive. Existing registry IDs, eligibility, histories, money, receipts and hashes are not rewritten. Plans and results contain private synthetic data; they use the same protected database, not browser persistence. The UI retains the selected file and plan after a request error. Offline controls send nothing and reconnect never imports automatically. Session termination discards the UI context; a page reload requires selecting and previewing a file again. Completed imports remain in the registry. There is no persistent offline import queue, arbitrary institutional CSV mapper or production-scale masterlist claim.
