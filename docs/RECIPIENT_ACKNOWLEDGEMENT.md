# Synthetic recipient acknowledgement

A Beneficiary account can open its recorded payout's receipt and explicitly select **I acknowledge this synthetic payout for my linked household**, then **Acknowledge demo payout**. Office readers see the result without an action. Public reference/hash verification does not disclose acknowledgement data.

This records an authenticated account's synthetic acknowledgement, not proof that a real person received cash. Payout recorded status, blockchain anchor status and acknowledgement are separate facts. The receipt hash is unchanged by acknowledging. The saved record captures the payout reference, linked household, batch, exact integer centavos, receipt hash, authenticated account ID/display name and UTC time. It is a local database/audit record, not an independently anchored delivery proof.

POST /api/distributions/{id}/acknowledgement requires the linked Beneficiary session, existing CSRF/origin checks and explicit acknowledge:true consent. Identity cannot be supplied by the caller. Staff, DSWD and Auditor cannot acknowledge on behalf of a household. GET and private distribution projections show the result only within existing payout scopes; Barangay has no named payout access. The new recipient_acknowledgements table is additive, with one acknowledgement per payout. SQLite serializes the scoped status/read/write and atomically saves acknowledgement plus the RECIPIENT_ACKNOWLEDGED local audit. Repeated/concurrent requests return the first saved result. A second linked account cannot replace the first actor.

New acknowledgements require a CONFIRMED recorded payout. Reversed/nonconfirmed records reject a new acknowledgement. Existing acknowledgements are retained if a record later reverses or its household becomes a retained duplicate; they remain historical statements, not renewed confirmation. This feature adds no reversal/dispute/retraction or assisted staff acknowledgement policy.

UI failure retains consent and offers retry for the same exact payout. Controls guard repeated clicks and offline calls; reconnect never submits automatically. Session end clears the private view. Refresh restores the saved acknowledgement from the real API. Already downloaded records are not erased by logout.
