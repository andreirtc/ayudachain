# MVP evidence protocol and local registry

2026-10-10. Accepted by the maintainer's execution request. This decision precedes implementation. It does not establish operational readiness.

FastAPI `backend/app/main.py` is the sole MVP API; PostgreSQL is its new database. `backend/server.py`, legacy models, legacy SQLite files and receipt hashes remain separate and receive no MVP writes. Local synthetic evaluation has selectable claimed, unverified identities, no login gate. Government signature integration is deferred: original evidence and printed signatories remain `not_validated`.

## Canonical private protocol

Protocol is `ayudachain.evidence.v1`. Content hash is SHA-256 of ASCII `AYUDACHAIN-EVIDENCE-v1\n` followed by exact canonical UTF-8 bytes. This restricted JSON is not RFC 8785. Object keys are unique ASCII snake_case, sorted by ASCII order. Arrays preserve their documented relational ordinal order. Values are strings, null, booleans, arrays or objects; numeric literals, undefined, duplicate keys and unpaired surrogates are rejected. Strings normalize to NFC when frozen. Encode non-ASCII literally. Escape quote/backslash and U+0000..U+001F using JSON short escapes for backspace, tab, newline, form feed and carriage return, otherwise lowercase `\u00xx`; do not escape slash, DEL, U+2028 or U+2029. Python uses ensure_ascii=False, sort_keys=True, separators=(',', ':'); Node uses a recursively sorted object and JSON.stringify after validation/normalization.

Envelope fields: protocol, kind, public_id, owner, context, predecessor, related, effective_at, actor, evidence, payload, private_nonce. Private IDs are canonical lowercase UUIDs; public IDs and nonce are lowercase bytes32 hex. Decimal money/counts are strings; times are fixed millisecond UTC. Actor includes claimed assurance/name/position-at-action, never credential material. Evidence descriptors bind immutable evidence ID, raw digest, length and MIME. Saved bytes are normative; a retry never freezes a second envelope or nonce. No code, PIN, digest/salt used for credentials, signer key or signed transaction belongs in material. Vectors for all ten kinds were computed and independently compared by Python and Node during T03 before use; actual saved originals/envelopes are also tested against signer-free pinned reads.

## Public registry

A separate `AyudaChainEvidenceRegistry` leaves `AyudaChainRegistry.sol` unchanged. Deployment constructor takes a random bytes32 UID, immutable operator and UID. Null public references use zero bytes32. All IDs/context handles are random bytes32 unrelated to DFC/person/contact IDs. Safe codes: 1 document, 2 amount_input, 3 barangay_submission, 4 system_fallback, 5 approved_list, 6 handover, 7 outcome, 8 fund_release, 9 fund_reversal, 10 fund_replacement. Every outcome uses code 7; no answer label or private amount appears in generic events. Fund amounts alone are explicitly public integer centavos.

`anchorRecord(bytes32 id,bytes32 hash,uint8 kind,bytes32 context,bytes32 predecessor,bytes32 related)` accepts generic kinds 1..7 once, nonzero id/hash/context, operator only. A nonzero predecessor must exist with compatible kind/context; a nonzero related must exist. Outcome related is its handover, kind 6. Document predecessor is a prior document; input/list/outcome successors have their same-kind predecessor.

`recordFundRelease(bytes32 entry,bytes32 disaster,uint256 amountCentavos,bytes32 hash)` records kind 8 and a positive signed delta with initial root = entry. `recordFundCorrection(bytes32 set,bytes32 original,bytes32 reversal,bytes32 reversalHash,bytes32 replacement,bytes32 replacementHash,uint256 replacementCentavos)` atomically records kinds 9/10, negative original amount and positive replacement amount; emits set/original/root links. Original must be current live positive release/replacement; a source can have one live successor. No new cash/budget/payout rule is inferred. Maximum absolute amount is 9e18. Duplicate/zero/correction/lineage failures revert entirely. Getters `records(id)`, `funds(id)`, `corrections(set)` and `deploymentUid()` expose only these safe fields. Events bind actual IDs and hashes for receipt reconciliation.

## Pinning and recovery

Only loopback local chain ID 31337, with separate evaluation and fault-test manifests. Manifest pins UID, chain ID, address, genesis hash, deployment block number/hash, runtime code hash, ABI path/hash and one-successful-mined-block policy. Deploy scripts alone generate ABI/manifests; API startup never deploys, resets, drops or seeds. The explicit local supervisor provisions reference records idempotently and deploys only when its selected manifest is absent; an existing missing deployment is refused. Loss/mismatch never selects the latest deployment. Read verification requires no signing key. Legacy reads use explicitly imported original deployment and original ABI/protocol, never the new registry.

Business record, typed audit and job intent commit atomically. No RPC occurs under business locks. Worker serializes signer nonce, persists exact signed transaction and derived candidate hash before send, reconciles actual receipt/getter/events after restart or uncertain send, and never invents observed references. A matching mined observation is applied once under the office lock; stale list candidates cannot publish. Funding counts and handover remains consumed during outages. Current integrity is a fresh read; historical checks cannot supply a green current result.

## Compatibility and tooling

Legacy `compute_receipt_hash` remains byte-for-byte unchanged (including old amount formatting, OCR normalization and limited coverage). Legacy contract storage/public functions and generated artifacts are untouched. New centavos/bytes32 never pass through legacy parseEther/text truncation. Shared fail-open service repair is allowed only to return honest explicit failures, not to migrate data.

Approved dependencies: existing FastAPI/Pydantic/SQLAlchemy/uvicorn/multipart; psycopg/alembic/pypdf/httpx; Node pg; development Playwright/openapi-typescript. Exact resolved locks accompany setup. No auth/SMS/cloud service added. PostgreSQL 18 local binaries and maintained Node 22/24 are supported tooling, not external services. Runtime credentials and HMAC key stay in ignored environment configuration. Private originals stay outside public/static mounts. Local evaluation ports are 3000/8000/8545; faults use 3001/8001/8555 and separate DB. An owned local PostgreSQL may use 55432 to avoid existing installations.
