# Usability additions — 12 October 2026

Implemented in `mvp-full` on top of the existing five-role workflow. The `main-2` implementation was read-only reference: its CSV analyzer, example selector and cosmetic offline toggle were not imported as capabilities. No dependency, schema, contract interface, commitment payload or original receipt hash changes were needed. Historical ideation is preserved.

| Addition | Entry point and delivered behavior |
|---|---|
| Scoped task queues | Each workspace's **Search & task queues** at `/queues`. POST search sends text in the body, filters/counts on the server, returns 25 rows (maximum 50), and includes safe direct record links. Names, household references, zone and permitted barangay/workflow filters; beneficiaries have own records only. Disbursing lookup omits household zone and private outcomes. Search text persists in tab session storage keyed by actor/disaster/queue, never in URLs. Safe filters/page persist in the URL. |
| Duplicate review | Claims screen. New checks freeze compared names, birth dates, addresses, registry/member/link versions in existing JSON evidence. Read-only comparisons for Auditor, current-check acknowledgment and existing human decisions for DSWD. Current revision/check changes clear individual and bulk acknowledgment. Explicit recheck is an audited, idempotent DSWD command. Historical flags lacking frozen evidence say unavailable; current private identity inspection uses the existing logged record endpoint. |
| Filipino guidance | Persistent English/Filipino guidance preference in the workspace context bar. Complete paired guidance for registration, claim/correction, endorsement, appointment, calculation, authorization, handover and private answer; translated consequential feedback and language metadata. Surrounding operational controls retain English fallback. Draft Filipino copy has not received native-speaker or institutional review. |
| Operations table | DSWD, Auditor and Barangay overview. Current claims/non-cancelled entitlements, distinct handovers and latest answers; missing amounts show a known subtotal plus count. Ready scheduling excludes current assigned appointments. Retained closed/cancelled/removed session memberships are excluded from assigned counts. Barangay sees own approved/handover/remaining totals only, with no payout drill-down. Permitted cells link to filtered queues. Funding authority remains separate from physical site cash. |
| Contextual evidence | Existing receipt/fund/list check panels now explain recorded content versus chain commitment, server check time and observed pinned chain references when available; raw hashes are expandable. A selected proof queue link opens its exact covered versions/original descriptors. Auditor history links open the authorized record. Integrity filters distinguish proofs checked this visit from historical submission states; no unperformed check implies success. |
| CSV intake | Registry for Barangay and DSWD staff only (screen storytelling follow-up, 2026-10-14: the Beneficiary screen no longer offers it; beneficiaries register through the household form, and the API route is unchanged). Download template, UTF-8 file, read-only validation/duplicate preview, explicit row selection, normal audited registration and per-row outcomes. 256 KiB/100-row limits; the API still caps a beneficiary at one row. Accepted columns: `name,birth_date,address,zone,declared_barangay_id`. Blank birth date is unknown. Templates are head-only no-ID declarations; identity/contact and additional members use normal permitted workflows. Prohibited/unknown/duplicate headers are rejected. Possible duplicate rows need ordinary human review and are not silently imported. |
| Scan/manual open | Disbursing payout screen in current assigned sessions. Native `BarcodeDetector` decodes QR frames when supported, with camera cleanup, denial/unsupported/cancel handling, repeat suppression and equal manual lookup. QR reference `ayudachain:transaction:<transaction UUID>` contains no personal data or secrets. A server read checks current assignment, session membership/version and scope. It only opens existing controls; photo ID, computed amount, recipient authorization, checker independence and online once-only handover remain unchanged. |

## CSV confirmation and recovery

Preview creates no household, eligibility decision or audit business action. Invalid and duplicate rows are excluded from confirmation. Confirmation revalidates the file and current scope, checks duplicates again under the existing office command lock, then uses `registry.register`. Successful rows remain saved if another row fails. Cancel before confirmation writes nothing; cancellation or a lost reply during confirmation cannot undo successful rows. Re-upload the identical canonical file to recover per-row saved references. Actor/content/row-derived command keys prevent a repeat upload or uncertain retry from creating another household/audit action. Ordinary residence checking, claim submission, independent endorsement and DSWD decision remain required.

## Assurance and validation limits

Selectable actors remain claimed, unverified and impersonable. These are server projections/workflow checks, not production privacy or authenticated accountability. Synthetic records only. National ID and notice SMS remain simulations; signatures remain not validated. Auditor creates no business mutations. Existing inspection logging applies to Auditor private reads; it does not provide a new staff lookup access log.

The local evaluation and fault chains were unavailable during this change. Pinned manifests and data were preserved; no contract redeployment or evaluation reset was performed to obtain passing tests. Matching/absent/mismatch chain reads and actual published-session lookup therefore require follow-up validation with the retained deployments restored. Existing fail-closed behavior remains. Browser decoder fixtures exercise the scan/result/cleanup path; physical camera hardware and native decoder performance were not validated. Advanced operations totals with successor lists, revised outcomes and locked payments use existing immutable/current-pointer queries but still require the full chain-backed journey regression.

See [validation](validation.md) for actual commands/results. Authentication, offline payout, new public transparency pages, formal audit exports and financial advances/liquidation remain deferred; none are implied by these additions.
