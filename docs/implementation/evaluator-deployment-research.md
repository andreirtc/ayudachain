# Evaluator deployment research

Checked 2026-10-12 against provider documentation and first-party source. Research only: no provider account, installation, resource, contract deployment or external access was created. Application requirements below come from [the handoff](evaluator-deployment-handoff.md); provider support does not establish that AyudaChain has passed a hosted deployment test.

Evaluation mode, accounts/domain, spending ceiling, chain/history, dataset and final architecture/tooling are **Pending** in the [deployment plan's decision register](evaluator-deployment-plan.md#pending-decisions). Recommendations in this research are conditional; the maintainer's authorization to commit and push the documents does not resolve those decisions.

## Recommendation and comparison

**Judgment:** prefer one VM with the production Next.js server, FastAPI, worker, scheduler, PostgreSQL and private originals for supervised evaluation. It removes a hosted-database compatibility change, database compute quota and several access/configuration boundaries while retaining the existing filesystem interface. Its cost and availability remain conditional. A VM's disk does **not** make the existing Hardhat chain durable. Unattended evaluation with preserved verification history remains blocked on an agreed, tested chain-recovery approach.

| Candidate | Consequence for this application | Conditions before selection |
|---|---|---|
| Vercel Hobby frontend + Neon Free database + Oracle VM for API/jobs/originals/private chain | Three hosting providers plus the access provider. Retains continuous VM processes but needs non-loopback database support, TLS, restricted Neon roles, direct worker sessions and coordinated backups. Neon quota can halt the entire workflow despite a healthy frontend. | Vercel personal/noncommercial eligibility; all accounts; Oracle capacity; actual Neon grants and direct-session tests; both origins gated; operating-hour budget. |
| One Oracle Always Free A1 VM for the whole application, local PostgreSQL, originals and existing private Hardhat | Fewer configuration boundaries; PostgreSQL and chain RPC remain on loopback. Operator owns database patching, supervision and coordinated external backups. Changes the cost condition, not chain durability. | Explicit budget approval, account/payment method, provider capacity, full acceptance tests and teardown/retention plan. |

These rows are architectural inference from the handoff and the verified constraints below, not deployed or measured outcomes.

## Verified provider constraints

**Oracle.** The current Always Free documentation specifies **1,500 OCPU-hours and 9,000 GB-hours/month: 2 OCPUs and 12 GB RAM**, not the older 4/24 allowance. Compute must be in the tenancy's home region; allocation can fail for lack of capacity. Included boot/block storage totals 200 GB, with five combined volume backups. Idle instances may be reclaimed when all listed seven-day thresholds hold: CPU 95th percentile below 20%, network below 20%, and A1 memory below 20%. Check actual tenancy limits; this is not a capacity reservation. [Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)

Most Oracle signups require a phone number and credit card; the card is not charged unless the account is upgraded. The $300/30-day trial is separate from recurring Always Free. Paid trial resources are reclaimed without an upgrade; excess A1 allocation can also be disabled/deleted. Do not solve capacity by silently upgrading or spending trial credits. [Oracle Free Tier](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier.htm)

**Neon.** The October 2 announcement confirms 1 GB PostgreSQL storage/project, 100 CU-hours/project/month and six hours of instant restore history. [Free-plan update](https://neon.com/blog/neon-free-plan-1-gb-per-project) The current FAQ additionally specifies 5 GB public network transfer/project/month; exhausted compute or transfer suspends the project's compute and drops connections until reset or upgrade. Free does not bill overages. [Current FAQ source](https://github.com/neondatabase/website/blob/main/content/faqs/free-plan-limits-and-quotas.md) Free compute suspends after five minutes of inactivity and that interval cannot be disabled. [Scale-to-zero source](https://github.com/neondatabase/website/blob/main/content/docs/introduction/scale-to-zero.md)

**Calculation/inference:** 100 CU-hours / 0.25 CU = 400 active hours, about 16.7 days. Thirty continuously active days at 0.25 CU require 180 CU-hours. The handoff's two-second database polling therefore threatens the Free allowance even without evaluators; larger autoscaling consumes it faster. Scheduled processing must stop and release activity between sessions, and actual suspension/usage must be measured. Slowing polling while still querying within five minutes does not establish idle time.

Neon roles created in its Console/API/CLI receive `neon_superuser` membership; SQL-created roles do not. Full PostgreSQL superuser access is unavailable. Create restricted application/worker/inspection logins through SQL, preserve required grants and role-switch permissions, and keep migration-owner credentials out of ordinary services. Compatibility still needs an actual migration and permission-denial test. [Neon roles source](https://github.com/neondatabase/website/blob/main/content/docs/manage/roles.md)

Neon pooling uses PgBouncer transaction mode and does not support session `SET`/`RESET` or session advisory locks. Use **direct** connections for the existing worker's session role/search path/locks, migrations and `pg_dump`; API pooling requires a separate compatibility review. [Neon pooling source](https://github.com/neondatabase/website/blob/main/content/docs/connect/connection-pooling.md)

**Vercel.** Hobby is free for personal/noncommercial use, and exceeded allowances can pause functionality. Eligibility for this evaluator project is not established. [Hobby documentation](https://vercel.com/docs/plans/hobby) Functions have a 4.5 MB request/response body limit and bounded invocation duration. A Function handling the handoff's 10 MiB originals or unchanged infinite loops is unsuitable without redesign. This constraint applies when traffic traverses a Function; do not assume every external rewrite has that same implementation. Verify the chosen upload route. [Function limits](https://vercel.com/docs/functions/limitations)

## Evaluator access and original uploads

Cloudflare Tunnel is available on all plans and makes outbound connections, allowing application origins without publicly open inbound service ports. [Tunnel documentation](https://developers.cloudflare.com/tunnel/) Access Free allows 50 users at $0; free support is community-based. [Current pricing](https://www.cloudflare.com/plans/) Zero Trust onboarding still requires payment details on Free, although Cloudflare says it will not charge for that plan. [Setup documentation](https://developers.cloudflare.com/cloudflare-one/setup/)

A stable named public Tunnel needs a domain in an active Cloudflare zone; the usual full setup adds the domain and changes its nameservers. Existing domain/control is unconfirmed and domain registration may add cost. [Tunnel prerequisites](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/create-local-tunnel/) Create the Access application before publishing routes. Cloudflare requires Access token validation at the origin, or `cloudflared` **Protect with Access**, to reject requests that bypass the gate. [Self-hosted Access instructions](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)

**Required preparation, not implemented:** use one gated hostname with ingress routing for frontend plus `/api/v1`, including original downloads. Bind frontend/API/database/RPC to loopback and block public application ports. Test direct IP, alternate hostnames and every original/API route without a valid session. If Vercel remains in the design, protect its provider deployment hostnames too; protecting only a custom Cloudflare hostname does not demonstrate bypass resistance. The gate identifies admitted evaluators, not the application's freely selectable claimed actors.

For a locally managed named Tunnel, the 2026.10.0 schema uses `originRequest.access.required: true`, `teamName` and `audTag` (an array). **Use the complete Access block on both API and frontend ingress rules:** although global defaults are merged, this version's `validateIngress` constructs JWT middleware from the raw per-rule `r.OriginRequest.Access`. Global-only configuration therefore does not establish enforcement. This is source inspection, not an executed connector test. [Configuration schema](https://github.com/cloudflare/cloudflared/blob/2026.10.0/config/configuration.go), [ingress middleware construction](https://github.com/cloudflare/cloudflared/blob/2026.10.0/ingress/ingress.go)

Cloudflare's documented Free upload ceiling is 100 MB and a zone can lower it. This is above 10 MiB, but the actual router, multipart overhead, timeouts, extraction and download path still require exact-limit streaming tests. Never bypass the gate to work around an upload failure. [Upload limits](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/4xx-client-error/error-413/)

### Conditional scheduled-session alternative: protected Quick Tunnel

Cloudflare added `--allowed-mail` on October 2, 2026: account/domain-free Quick Tunnels can require email one-time PINs for selected visitors. Its instructions require a current `cloudflared`. [Official announcement](https://developers.cloudflare.com/changelog/post/2026-10-02-protected-quick-tunnels/) The 2026.10.0 source registers the flag and constructs an authorizer for protected mode. [Flag source](https://github.com/cloudflare/cloudflared/blob/2026.10.0/cmd/cloudflared/tunnel/cmd.go), [protected-mode source](https://github.com/cloudflare/cloudflared/blob/2026.10.0/cmd/cloudflared/tunnel/quick_tunnel.go)

Quick Tunnels have no uptime guarantee, change hostname when recreated, allow 200 in-flight requests, exclude SSE, and require an interactive browser for email authentication. [Quick Tunnel limits](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) A firsthand report in Cloudflare's issue tracker describes five-second authenticated sessions on 2026.10.0, with a separate Windows report. It remained open when checked. **This is a reported issue, not a reproduced or provider-confirmed finding here.** [Issue #1752](https://github.com/cloudflare/cloudflared/issues/1752)

**Judgment:** Quick Tunnel OTP is a useful experiment for supervised sessions when no domain/Access account exists, not the baseline until it passes the full journey. The single `--url` needs a tested local same-origin router or Next.js rewrite; current browser API fallbacks and original links must resolve through it. Acceptance must include an allowed and denied email, long-enough session, CSS/JS loading, concurrent actions, 10 MiB upload/download, expired-login POSTs and direct-origin denial. Keep the normal application/worker/private chain running locally; closing the temporary tunnel only closes evaluator ingress. Installing new tooling and opening the tunnel require the applicable approval boundary; neither happened in this research.

## Chain durability and other free hosts

Hardhat documentation describes a new in-memory network on startup and a standalone node for external clients. [Hardhat 2 getting started](https://v2.hardhat.org/hardhat-runner/docs/getting-started) **Inference for this application's existing node:** retaining PostgreSQL and original files cannot restore lost chain history. Automatic restart/redeployment must not remap historical pins or make old commitments appear verified. A persistent private EVM is a candidate needing separate tooling approval, compatibility tests and crash-recovery evidence; it is neither approved nor implemented by this note. Paying for a VM does not solve this constraint.

Anvil is one experimental candidate: current first-party CLI source supports state load/dump, periodic dumps and optional historical states; it also exposes history-pruning/transaction-retention controls. [Anvil CLI source](https://github.com/foundry-rs/foundry/blob/master/crates/anvil/src/cmd.rs) **Inference:** a snapshot facility does not prove preservation after a hard kill between dumps. Before proposing a replacement, pin the executable version and test unchanged contract bytecode/ABI, genesis and deployment block hashes, transaction receipts/events, historical reads, and pending nonce/signed-transaction recovery across graceful and forced termination. Those compatibility/crash probes are unrun; no Anvil installation or dependency addition is authorized by this note. Restoring account/storage values alone is insufficient evidence for this registry's provenance and worker recovery.

Render Free sleeps after 15 minutes without inbound traffic, loses filesystem changes on redeploy/restart/sleep, cannot attach persistent disks, and offers Free only for listed service types rather than dedicated workers. Its free PostgreSQL expires after 30 days. [Render Free documentation](https://render.com/docs/free) Koyeb Free has 512 MB RAM/0.1 vCPU, sleeps after one hour without traffic, and cannot be a Worker Service or use volumes. [Koyeb instance documentation](https://www.koyeb.com/docs/reference/instances) These facts rule out an unchanged complete continuous/durable stack. Artificial keepalive traffic is not the proposed solution.

## Fixed-cost fallback and remaining proof

If Oracle cannot be allocated in time or reclamation risk is unacceptable, DigitalOcean advertises a **Basic Regular 2 vCPU/4 GiB/80 GiB** Droplet at **$24/month base cap**, including 4,000 GiB transfer. This is a credible VM candidate, not a demonstrated sizing minimum or all-in quote; backups, snapshots, domain, taxes and excess usage need a concrete budget. [Droplet pricing](https://www.digitalocean.com/pricing/droplets) Bundled Droplets continue billing while powered off; billing ends on destruction. Preservation/teardown therefore requires planned backup retention. [Billing details](https://docs.digitalocean.com/products/droplets/details/pricing/) DigitalOcean supports card/debit and third-party payment methods, with automatic settlement of balances. [Payment documentation](https://docs.digitalocean.com/platform/billing/pay-bills/) Singapore is an available region; actual capacity and Philippine network latency are unmeasured. [Regional availability](https://docs.digitalocean.com/platform/regional-availability/)

No provider account access, concurrency measurements, Linux/ARM runtime, browser gate, remote camera, upload-through-tunnel or chain-restart acceptance was validated here. Next steps depend on scheduled versus unattended access, available accounts/domain, explicit spending ceiling and required retained-chain history. Scheduled sessions can use the current private node with an honest loss/recovery procedure; unattended history continuity requires the chain decision first. Backups must preserve database, private original bytes, replay key and pinned deployment provenance together, and be recoverable outside the sole VM. Provider restore windows or volume snapshots alone do not prove that recovery.
